# v.kochneva. Yandex Disk API. 

Репозиторий содержит проект автоматизированного гибридного тестирования (UI + API) для облачного сервиса Яндекс.Диск.

Проект проверяет бесшовную синхронизацию данных: действия, совершаемые через отправку запросов к REST API Яндекса, мгновенно проверяются в интерфейсе браузера без принудительного обновления страницы (и наоборот).

Для автоматизации интерфейса используется библиотека py_selenium_auto (обертка над Selenium WebDriver), для работы с API - клиент на базе библиотеки requests, а для валидации тестовых данных - библиотека pydantic.

## Как запустить проект
1. Клонировать репозиторий:

```bash
git clone https://github.com/vikochk/testing-yandex-api.git
cd <project_folder>
```

2. Установить Python 3.11+.

Если используется pyenv:

```bash
pyenv install
```

3. Создать виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate    # Linux/macOS
.venv\Scripts\activate.bat   # Windows
```

4. Установить зависимости:

```bash
pip install -r requirements.txt
```

5. Проверить конфигурацию тестовых данных в папке `tests/resources/`

Внутри папки находятся файлы `test_user_data.json` и `yandex_disk_data.json`. Перед запуском тестов обязательно заполните в файле `test_user_data.json` ваши авторизационные данные и OAuth-токен. Пример содержимого:

```
{
    "login" : "my_login",
    "password" : "1234567",
    "oauth": "y0__1234567"
}
```

6. Запустить тесты: `python -m pytest tests/test_yandex_api.py`

```

│   ├── api/         # Клиент для работы с Yandex Disk API (YandexApiClient)

```

### Реализованные тесты

В проекте реализован сквозной интеграционный сценарий (test_yandex_api в файле tests/test_yandex_api.py), сочетающий UI и API проверки:

Шаг 1-2 [UI]: переход на страницу Яндекс.Диска и авторизация пользователя по логину и паролю. Предусмотрена обработка окон подтверждения (Push-уведомления, предложения входа по отпечатку пальца).

Шаг 3-5 [API -> UI]: загрузка текстового файла со случайным содержимым через API. Проверка в интерфейсе браузера (без перезагрузки страницы), что файл появился на диске. Открытие файла двойным кликом в новой вкладке и верификация его содержимого на соответствие отправленному.

Шаг 6-7 [API -> UI]: переименование файла и изменение его расширения с .txt на .jpg через API-запрос. Проверка динамического обновления на UI (появление нового .jpg файла и исчезновение старого .txt).

Шаг 8-9 [API -> UI]: замена измененного файла полноценным бинарным изображением через API. Открытие превью изображения на UI и попиксельное сравнение отображаемой картинки с отправленным оригиналом.

Шаг 10-11 [UI -> API]: перетаскивание файла изображения в Корзину через интерфейс (Drag & Drop). API-запрос к корзине для проверки успешного удаления и корректности метаданных файла в корзине.

Шаг 12-13 [API -> UI]: восстановление файла из Корзины через API. Проверка на UI (без перезагрузки страницы), что восстановленный файл вновь присутствует в списке.

Шаг 14-15 [API -> UI]: безвозвратное удаление файла через API. Окончательное подтверждение исчезновения файла на интерфейсе браузера.
